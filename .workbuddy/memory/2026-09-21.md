
## 底层改造：盘中资金流全实时化（用户"彻底修改底层，盘中的分析都需要用实时数据"）

### 问题根因
SS分资金面55%权重里，真正用到"资金流"的只有第8类（main_5d/main_20d/inflow_rate，±5~8分）。这几个字段来自 get_fund_flows，其 SQL 是 `date<=today ORDER BY date DESC LIMIT 1`——盘中库里没有"当日"记录时，回退读的是**昨收口径**。导致盘中 SS 排名滞后。

### 解决方案（已验证生效）
1. **新建 refresh_fundflow_realtime.py**：用 westock CLI（`~/.local/bin/westock fund flow <代码串>`，独立二进制，脚本可直连，每批10只）全池拉当日实时资金流（EndDate=今日，MainNetFlow=当日实时净额，5D/20D=实时累计），写 fund_flows 当日记录。参数：`--pool-only`(持仓+focus+共识约59只) / `--dry-run`(不写库)。461只全池约2分钟拉完459只(缺2只北交所 832571/920808)。
2. **run_focus.sh 改造**：引擎前新增【0/3】步骤，`HOUR>=9` 时自动跑 refresh_fundflow_realtime.py，盘前跳过（未开盘无实时）；`--no-fundflow` 手动降级。
3. **关键澄清**：westock CLI 的 5D/20D 就是"实时累计"口径（含当日盘中），与 tdx 逐日收盘拼合在收盘后等价，故**无需再走 tdx 逐只转录**的繁琐流程（9/17 曾卡90分钟）。
